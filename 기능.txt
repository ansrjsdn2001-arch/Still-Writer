Still Writer 기능 정리
최신화 기준: 2026-07-30

1. 기본 개발 정책

- 프론트엔드는 Vite / React 기반으로 구현한다.
- 프론트엔드 개발 서버는 http://localhost:5173 을 사용한다.
- 백엔드 서버는 http://localhost:8080 을 사용한다.
- 프론트엔드의 /api 요청은 Vite proxy를 통해 백엔드로 전달한다.
- Access Token은 sessionStorage에 저장한다.
- Refresh Token은 백엔드가 HttpOnly 쿠키로 발급하며, 프론트엔드 JavaScript에서 직접 읽거나 저장하지 않는다.
- 비밀번호, 이메일 인증 코드, OAuth 토큰 원문은 console에 출력하지 않는다.
- 글 작성, 글 목록, 즐겨찾기, 소재, 휴지통, 프로필 등 사용자 데이터가 필요한 기능은 로그인 회원 전용으로 운영한다.

4. 인증 기능 상세

4-1. 일반 회원가입

- 이메일, 인증 코드, 닉네임, 비밀번호, 비밀번호 확인, 약관 동의를 입력한다.
- 이메일 형식이 올바르지 않으면 API 호출 전에 프론트에서 먼저 안내한다.
- 인증 메일 발송 성공 후 인증 코드 입력란을 활성화한다.
- 인증 코드는 영문 대문자, 영문 소문자, 숫자로 구성된 6자리만 입력할 수 있다.
- 인증 코드 유효 시간은 3분이다.
- 3분 카운트다운을 표시한다.
- 인증 메일 재발송은 최소 30초 대기 후 가능하다.
- 이메일 인증 완료 전에는 회원가입 버튼을 통한 실제 가입을 막는다.
- 인증 완료 후 이메일 입력값이 변경되면 인증 상태를 초기화한다.
- 비밀번호와 인증 코드는 localStorage/sessionStorage에 저장하지 않는다.

4-2. 일반 로그인

- 이메일과 비밀번호로 로그인한다.
- 로그인 성공 시 Access Token은 sessionStorage에 저장한다.
- 사용자 표시 정보는 still-writer-user로 저장한다.
- 로그인 유지 체크 시 사용자 표시 정보는 localStorage에 저장한다.
- 로그인 유지 미체크 시 사용자 표시 정보는 sessionStorage에 저장한다.
- Refresh Token은 백엔드 HttpOnly 쿠키에만 존재한다.

4-3. Google / Kakao 소셜 로그인

- Google과 Kakao 로그인 시작 버튼을 제공한다.
- 백엔드 OAuth 인증 완료 후 프론트 콜백 경로에서 로그인 결과를 처리한다.
- 콜백 경로는 다음과 같다.
  - Google: /oauth/google/callback
  - Kakao: /oauth/kakao/callback
- OAuth callback은 공용 OAuthCallback 컴포넌트에서 provider 값을 받아 처리한다.
- provider에 따라 처리 중 문구와 오류 문구를 구분한다.
- React StrictMode 환경에서 Effect가 두 번 실행되어도 OAuth 결과를 중복 처리하지 않는다.
- URL hash에 포함된 Access Token은 처리 직후 history.replaceState로 제거한다.
- OAuth 결과를 처음부터 전달받지 못한 경우에만 실패로 처리하고 /login으로 이동한다.


5. 글 작성 정책

- 글 작성은 로그인한 회원만 사용할 수 있게 운영한다.
- 비로그인 임시 글 작성은 현재 우선순위에서 제외한다.
- 이유:
  - 비로그인 상태에서는 서버 DB에 사용자 기준으로 안정적으로 자동저장하기 어렵다.
  - localStorage나 IndexedDB 기반 임시저장은 브라우저 데이터 삭제, 시크릿 모드, 기기 변경에 취약하다.
  - 작업물이 사라지는 문제를 줄이려면 로그인 사용자 ID 기준의 서버 자동저장이 더 안정적이다.
- 권장 구현 방향:
  - 비로그인 사용자가 /write 접근 시 /login으로 이동시킨다.
  - 로그인 성공 후 원래 접근하려던 경로로 되돌아갈 수 있게 한다.
  - 작성 중 제목/본문 변경 시 debounce 자동저장을 적용한다.
  - 저장 상태를 표시한다.
    - 저장 중
    - 방금 저장됨
    - 저장 실패, 다시 시도 중
  - Access Token 만료 시 Refresh Token 쿠키 기반 재발급 후 저장 요청을 재시도한다.


6. 폴더 / 글 분류 정책

- 폴더 카테고리는 다음을 기준으로 한다.
  - 소설
  - 일기
  - 메모
- 소설 폴더:
  - 글 생성 시 목표 글자 수를 설정할 수 있다.
  - 목표 글자 수 설정은 체크박스로 활성화/비활성화할 수 있다.
  - 목표 글자 수 달성 여부를 판단한다.
- 일기 폴더:
  - 생성 시 날짜를 자동 기입할 수 있다.
  - 날짜 자동 기입은 체크박스로 활성화/비활성화할 수 있다.
  - 일기 연속 작성 여부를 판단한다.
  - 일기 내용은 소재로 이동할 수 있다.
- 메모 폴더:
  - 별도 설정 없이 생성한다.
  - 메모 내용은 소재로 이동할 수 있다.
- 폴더 이름은 사용자가 설정할 수 있다.


7. UI / 테마 정책

- 라이트 모드와 다크 모드를 지원한다.
- 홈, 로그인, 회원가입 화면의 배경 이미지는 테마에 따라 변경한다.
  - 라이트: /images/heroimage(light).png
  - 다크: /images/heroimage(dark).png
- 로그인/회원가입 화면은 다크모드에서 다크 이미지가 밝은 오버레이에 묻히지 않도록 다크 전용 오버레이를 사용한다.
- 포인트 색상을 사용하는 주요 버튼은 테마 변경과 관계없이 기존 포인트 색상을 유지한다.
